## 2. 逐个分析

### 2.1 OCS（`ocsjs/ocsjs`）— 智慧树 DOM 知识的唯一富矿

MIT，pnpm workspace（`packages/core`、`scripts`、`utils`）。
关键文件 **`packages/scripts/src/projects/zhs.ts`（3620 行 / 112 KB）**，
是四个项目里对智慧树覆盖最全的一份实现。

它按"页面类型"分处理器（`ZHSProcessor` 接口），每个处理器实现
`getCourseName` / `getChapterName` / `getNext` / `hasJob` / `handleTestDialog`：

| 处理器 | 页面 | 视频条目选择器 | 已完成标记 |
|---|---|---|---|
| `StudyVideoH5` | 经典共享课 `studyvideoh5` | `.clearfix.video` / 当前 `.current_play` | `.time_icofinish` |
| `FusionCourseH5` | AI 助教课 `fusioncourseh5` | `.resources-item` / `.activeNode` | `.isFinish`、`.progress-num` |
| `StudyPlusH5` | 新共享课 `studyplush5` | `.child-main` / `.current` | `.finish-icon` |
| `WishdomH5` | 2025-9 新智慧 `studywisdomh5` | `.chapter-content .chapter-item` / `.current` | `.finish-icon` |
| `Hike` / `HikeV2` | 教学空间 | `.source-icon` | — |

**弹题（课中弹题）检测——这是 OCS 最有价值的部分**，三种页面三种弹窗：

| 页面 | 弹窗根节点 | 选项 | 提交按钮 | 关闭按钮 |
|---|---|---|---|---|
| 经典共享课 | `#playTopic-dialog` | `.topic .radio ul > li` | `#playTopic-dialog .btn` | `.close-btn` |
| 新共享课 | `.ai-test-question-wrapper` | `.options .option` | `.submit-btn .submits` | `.close-box` |
| 新智慧/AI助教 | `.ai-class-exercise-dialog` | `.ques-list .item .option` | `.el-dialog__footer .el-button.btn` | `.header-icon` |

> ⚠️ **OCS 对弹题的处理是"随机选一个"**（`Math.floor(Math.random() * options.length)`）。
> 本项目要把它换成"读取题目 → Agent/LLM 作答"（用户目标 3）——这是**我们相对上游的增量**，
> 也是必须自研、不能复用的那一小块。

播放控制：`.controlsBar`、倍速 `.speedList [rate="X"]`、线路 `.definiLines .line1bq/.line1gq`。
杂项：`optimizeSecond` / `autoStop` / `fixProcessBar` / `closeDialogRead` / `finishAlert`。

**为什么不能直接跑 OCS**：它是 Vite 构建的 TypeScript 用户脚本，要产出 bundle
再装进用户脚本管理器。让统一层去 subprocess 一个"需要浏览器扩展宿主"的东西，
不如把它的**知识**（选择器 + 分类）拿过来，由本项目自建的浏览器通道执行。

### 2.2 Autovisor（`CXRunfree/Autovisor`）— 唯一可 subprocess 的主力

MIT，Python 3.10–3.13，Playwright，`pyproject.toml` 依赖
`httpx / pillow / playwright / pygetwindow(win) / requests`，可选 `numpy+opencv`（滑块）。

结构（`modules/`，语义很清楚）：

```
course_runner.py    run_course() / detect_catalog_after_verification()   ← 课程主编排
course_playback.py                                                       ← 播放
lesson_navigation.py                                                     ← 章节切换
progress.py                                                              ← 进度检测
video_state.py                                                           ← 视频状态机
tasks.py            play_video / skip_questions / task_monitor / video_optimize / wait_for_verify
login.py            登录（含智慧树新版登录页）
slider.py           滑块验证
diagnostics.py      --check-browser / --check-course（只读，无副作用！）
configs.py / installer.py / updater.py / logger.py
```

README 自述已覆盖的能力（对应用户目标 2）：

- ✅ 课程类型：智慧共享课新版目录、翻转课、旧版课程，自动识别目录结构
- ✅ **进度检测**：检测平台实际进度，未确认完成时自动回退重试
- ✅ **停滞保护**：视频与平台进度长时间无推进时自动停止
- ✅ **弹题期间暂停播放**，且等待时间不计入课程时限 ← 注意是"暂停"，不是"作答"
- ✅ 倍速上限 1.8（`limitSpeed`）、静音、每课限时（`limitMaxTime`）
- ✅ 多课程链接（`URL1..URLn`）、cookie 复用（`data/cookies.json`）
- ✅ 只读诊断命令，不刷课、不上报进度

**接入方式**：生成 `config.ini` 写到账号工作区 → `python Autovisor.py` 子进程 →
流式解析 stdout 报告进度 → 退出码判定。**上游零改动**（红线 R2）。

**它的缺口（= 我们要补的）**：弹题只暂停不作答；没有"读取题目"的结构化出口；
没有按任务点粒度的暂停/断点；失败原因在日志文本里，不是机器可读的。

### 2.3 zhihuishu-zhangwodu（`Cooanyh`）— 掌握度答题的流程参考

CC BY-NC-SA 4.0，单文件用户脚本，`@match` 覆盖：

```
studywisdomh5.zhihuishu.com/{study*,exam*,pointOfMastery*}
wisdom-mooc.zhihuishu.com/{study*,exam*,pointOfMastery*}
```

提供的关键流程知识（仅参考，不复制代码）：

1. **任务发现**：自动定位"知识点掌握"页里未完成的**灰色知识点**，
   可选做**红色薄弱点**（默认只做灰色）。
2. **逐页答题 → 翻页 → 提交**，直到该知识点全部题做完。
3. **题库优先**：Levenshtein 距离做 **90% 模糊匹配**，未命中再回落 AI。
4. 多布局适配：`/study/mastery` 与 `/study/analysis`。
5. AI 服务商可 Fallback（DeepSeek / Zhipu / OpenAI / Gemini / Coren）。

**许可证处理**：NC（禁止商用）+ SA（衍生作品必须同许可证）→ 纳入即污染整仓许可。
本项目**只读它的思路**，实现用自己的代码。这也正好对上用户原则
"禁止为了代码干净而重写已经可用的能力"——但这里**不是**可用的代码，是许可证不可用的代码。

### 2.4 zhihuishu-resource-helper（`Finn-Holmes`）— 新形态课程页面参考

**仓库内没有 LICENSE 文件**（`package.json` 有 `private: true`，也没有 license 字段）。
按著作权法默认 **"保留所有权利"**。`@match ai-smart-course-student-pro.zhihuishu.com`。

仅记录其页面选择器约定（这是"页面事实"，不是代码）：

```
.section-item-collapse .section-item-collapse-info   # 知识点条目
.section-item-collapse-title .title-text             # 知识点名称
#middle-section-id .point-title-text                 # 当前小节标题
#middle-section-id .resources-section                # 资源区
.basic-info-video-card-container                     # 视频卡片
h5.video-title                                       # 视频标题
#middle-section-id .preview-content                  # 预览区
```

它的行为特征是"逐个打开资源 + 刷新接续 + 完成状态检查 + 日志导出"，
还带一个 jsdom 单测（`tests/opener.test.cjs`）。

**结论**：新形态课程这一支，本项目**先只做只读盘点**（列出资源、读进度），
不做自动播放；等取得作者授权或改走自研选择器后再考虑写操作。

## 4. 可复用 / 不可复用清单

### 可直接 subprocess 调用
- `Autovisor`（MIT）：视频播放 / 切章 / 进度 / 停滞保护 / 弹题暂停 / 只读诊断

### 可复制代码（须保留声明）
- `ocsjs`（MIT）：`zhs.ts` 的**选择器常量 + 页面分类 + 弹题弹窗结构**
  → 落到 `orchestrator/adapters/zhs_dom.py`

### 只能只读参考（许可证障碍）
- `zhihuishu-zhangwodu`（CC BY-NC-SA）：掌握度任务发现 / 翻页 / 题库模糊匹配流程
- `zhihuishu-resource-helper`（无许可证）：新形态课程 DOM 结构

### 必须自研（上游都没有）
| 缺口 | 为什么上游没有 | 对应能力 |
|---|---|---|
| 弹题**读题 + Agent/LLM 作答** | OCS 随机选；Autovisor 只暂停 | `C43`–`C47` |
| 任务点粒度的**结构化扫描与断点** | 上游都是"跑完整课" | `C09`、`C40`、`C41` |
| **考试/监考页面的统一拦截** | 上游各自判断，无统一红线 | 本项目 `safety.py` |
| 机器可读的**统一错误分类** | 上游只有日志文本 | `errors.py` 8 分类 |

## 5. 相比两个姊妹项目的差异

| | `cx`（学习通） | `zhihui`（智慧职教） | **`zhihuishu`（本项目）** |
|---|---|---|---|
| 上游形态 | HTTP API（可纯请求） | HTTP API + 浏览器 | **必须以浏览器为主**（视频加密 + 弹题为 DOM） |
| 主力上游许可 | GPL-3.0（仅 subprocess） | PolyForm NC / 无许可 | **MIT**（可 subprocess 且可复制） |
| 登录 | 账密 AES + cookie | SSO Token 单点 | 扫码 / 账密 + 滑块 + cookie |
| 考试风险 | 有考试但未被专项拦截 | 同 | **明确列为红线，专门实现 `safety.py`** |

**关键差异**：智慧树的视频与弹题**无法脱离浏览器**，所以本项目
`C38 浏览器自动化` 是**一等公民**而不是兜底——这与 `cx` 恰好相反。
