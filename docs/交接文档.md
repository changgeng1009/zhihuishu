## 一、这个项目是什么

把**第三方智慧树刷课工具**变成能被统一调用的能力平台。自研代码只在 `orchestrator/` 和 `scripts/`;第三方上游放 `upstreams/`(gitignore、锁 commit、**只读**)。

同架构的姊妹仓库(接口逐字一致,能力编号 C01–C51):
| 平台 | 本地路径 | GitHub | 备注 |
|---|---|---|---|
| 学习通 | `D:\CodexWork\学习通刷课脚本` | `changgeng1009/cx` | **能多批量并行,因为它走纯 API 心跳,不开浏览器** |
| 智慧职教 | `D:\CodexWork\智慧职教刷课` | `changgeng1009/zhihui` | |
| 智慧树 | 本仓库 | `changgeng1009/zhihuishu` | 必须真浏览器真播放(见下) |

**为什么智慧树不能像学习通那样并行**:学习通上游是纯 HTTP 库(发心跳包,零浏览器);智慧树所有接口带 `secretStr`(页面 JS 现场生成的签名),没有可直连的公开 API,播放进度由页面播放器自己上报。想并行只能真开多路视频,成本和风控都不可控。这个结论讨论过并封死了,**不要再提议逆向 secretStr**。

## 二、铁律(先读这个,违反会出事故)

1. **考试守卫判定顺序不许动**(`orchestrator/safety.py`):
   练习白名单 → 考试黑名单 → 学习页 → 其余转人工。
   原因:`examloop.zhihuishu.com/exam` 是正式考试,`studywisdomh5.zhihuishu.com/exam` 是掌握度练习——同一个路径在两个域语义相反。调换顺序 = 要么误杀练习,要么在正式考上自动作答(诚信事故)。
2. **不伪造进度**:心跳由页面播放器自己发。我们能做的是真实播放(1.5x 是平台 UI 档位上限)。不逆向签名、不直连接口、不改 `currentTime` 跳着播。
3. **`upstreams/` 一个字节都不改**(R2):可随时按 lock 重新拉取;有 `cli upstreams` 校验。
4. **一切产物只落在项目目录内**(R5):曾在 C 盘污染过,用户有硬规则。
5. 账号单写互斥、日志全量落 `runs/`(审计用),别删。

**弹题链路**(本项目相对上游的唯一增量):页面弹题 → 提取题面 → 原子写工单 `runs/answer/pending_*.json` → Agent/人作答,写 `answer_<ticket_id>.json` → 脚本轮询拿到 → 真实 CDP 鼠标点击选项 → 点提交 → **必须在页面见到「已提交」才算数** → 记入去重索引(同题重弹秒过,不再打扰人)。铁律:超时默认暂停转人工,绝不随机作答。

### 平台侧实证(设计依据,别再从头摸)
- 真实播放是**有效的**:0.1 从「未练习」→「掌握度40%」→ 条目出现绿色对勾
- 任务条目有**平台稳定 id**:`<div class="child-info hasvideo" id="part1000129959">`——定位/断点/证据全用它
- 完成态的**可视化标记是图标**:完成 = 绿色对勾,观看中 = Element-Plus `.el-progress` 蓝色环(`aria-valuenow` = 百分比),未开始 = 无环。**不是文字**,按文案搜「已练习/完成」永远搜不到(踩过)
- 条目标题后缀(「未练习」「掌握度40%」「免考」)会**漂移**,绝对不能当身份或匹配键(踩过:includes 不命中导致全量假 skip)

### 卡在哪里(当前唯一硬卡点)

**症状**:一讲视频播到结尾(ended)之后,这一页上的所有列表点击都失效——点击只挪高亮(`child-info.cur` 会移动),但播放器不加载新视频;伴随播放器错误态(「Sorry 您可能需要下载」)。

**已经试过并排除的方案**(别重复踩):
| 方案 | 结果 |
|---|---|
| `Page.navigate` 到相同 URL | 无效——SPA 原地不动,不算重载 |
| `Page.reload`(ignoreCache) | 首次加载后的点击有时能成功;但**播完 ended 后 reload 无效**,且会连累渲染进程崩溃(WinError 10053) |
| 播放器解卡(`currentTime=0; play()`) | 无效 |
| 隐藏降噪弹窗(el-dialog 等) | 该做(弹窗确实挡点击),但不解决本问题 |
| **整机重启浏览器(唯一有效)** | 全新启动后首点即成,今天 3 次实验 2 次成功——已接入 v5 主循环(`_relaunch`),**但恢复循环本身有 bug 未修完** |

**当前最前沿的一次运行**(v5_cleanC.log,2026-09-20 晚):第 1 讲正常播完 → 进入第 2 讲时 CDP 连接中断 → 整机重启 → 又立即连接中断 → 死循环。即 `_relaunch()` 的实现有问题,可疑点:
1. 旧浏览器进程没死透就 `B.launch`(profile 单例锁 `quiz_profile` 被占,新实例附着失败或抢不到调试端口 9334)
2. `_PageSession` 手工 `__enter__/__exit__` 的时序,`pick_page_target` 可能选到旧死标签
3. 启动后没等端口真正就绪就开始 cookie 恢复

### 下一步建议(按性价比排序)
1. **修 `_relaunch`**:重启前先确认 9334 端口释放(轮询 `connect_ex != 0`)、`proc.kill()` 代替 `terminate()`、启动后轮询 `probe_cdp` 直到 alive 再恢复 cookie。这是最小改动。
2. 若仍不稳,**切换到 Autovisor 通道做播放+切章**(项目原设计!v0.5 已跑通其运行时副本,`accounts/acc_01/autovisor/`,当时只差 MSE 缓冲推进的最后一关)。浏览器通道退回只做读侧+弹题。注意 Autovisor 会写 `upstreams/`,必须用 `worker._runtime_copy()` 的运行时副本。
3. 长期:摸清「免考」后缀语义——如果平台真把某些讲判免考,可能根本不用播。

## 五、容易被误解的地方(提前说清,省你半天)

1. **「视频元素消失/播到末尾」≠ 完成**。只有平台进度环 `aria-valuenow >= 100` 才计 confirmed,其余一律「待确认」单独分桶。宁慢勿假——这是设计立场,不是 bug。
2. **弹题返回值是结构化 dict**(`{"status","detail","verified"}`),不是字符串。早期版本返回字符串导致过越界崩溃,已钉死回归测试(`tests/test_popup_result.py`),别改回去。
3. **工单的去重索引**(`runs/answer/answered_keys.json`)是"答案知识库":key = 题干 sha1,value = 字母答案。删了它同题就要重新人工答。已有 3 题。
4. **点击必须用 CDP `Input.dispatchMouseEvent`**(isTrusted=true)。`el.click()` 会被风控识别(实测跳首页)。
5. **视频页禁止注入脚本**(平台有完整性检测,弹「检测到异常脚本」)。读侧只读 DOM,或用 CDP 层被动监听。
6. **CDP 事件监听**:同一个 ws 连接混用 call+监听会丢事件;要监听就开独立连接(`cdp.py` 有现成模式)。
7. **`HTTP_PROXY` 环境变量**:回环请求(127.0.0.1:9334)会被代理吃掉返回 502。项目里 `cdp.loopback_opener()` 已硬编码绕开,自己写回环 HTTP 必须用它。
8. **Windows/Git Bash 坑**:Bash 首条命令先 `export PATH="/usr/bin:/bin:/mingw64/bin:$PATH"` 否则 ls/mkdir 全没有;`.cmd` 文件纯 ASCII+CRLF;后台任务里 `cmd &` 会在任务结束时被杀(浏览器是批量子进程,杀批量=杀浏览器),要用真后台任务方式跑。
9. **测试是纯离线的**(FakePage 驱动),绿了不代表端到端通;端到端必须真实跑(`runs/*.log` 看证据)。反过来,别为了过端到端去改测试的断言。
